# v0.15：真实本地 QLoRA 参数进化

## 协议

Qwen3-4B 量化模型，最后八层共 367 万可训练适配参数。三个患者互不交叉的 600 例反馈块；普通采样与更新前错误优先采样每轮均用 400 例、100 步。两臂共用初始 8k 固定候选/订单工具、100 例损失验证、200 例选择检查及新的 500 次住院（494 位患者）测试。先冻结全部选择再评价测试。每轮重置优化器，继续训练最新适配器；推理保留检查集最优版本。模型权重、反馈和患者数据均只在本地。

## 到底进化了什么

每轮真实改变适配器权重文件和训练采样成员哈希；候选检索及联合订单模板固定。模型学习选择已有模板，没有学习新剂量生成。历史医嘱一致性不等于指征、DDI 或肾功能安全；已有 GT 可自动评分，不要求医生重新标注后才能计算。

同时保留原始/归一化有效率，仅去除 Qwen 空 reasoning 标签。解析和缓存修复发生在测试前，原始输出保留。已独立按药物集合及药物/途径/剂量/单位完整元组重算，并给出患者聚类配对区间；未知字段不计分。只比初始模型好还不能证明 RSI 优势，必须看错误优先是否优于普通更新，以及是否优于直接使用相同工具。

## 事先固定的干预

输出改为 20 位纳入/排除掩码，显式监督负候选。两臂均从原始模型重新开始；患者、候选工具、训练步数/样本数与 v0.9 一致，但目标 token 数不同。协议在 v0.9 测试前冻结。仅在逐例检查测试 ID、GT、候选目录完全相等后复用直接工具对照。

## 完整结论与失败诊断

两臂均在测试前选择第 2 轮。错误优先较普通更新提高药物 F1 0.05098、订单 F1 0.04257，患者聚类描述性区间均为正；仍比直接 top-8 工具低 0.01977/0.01410，区间均为负。这里只有一个学习种子，不能宣称稳健最优。ID 与二元表示的样本/步数相同，但目标 token 预算不同。

错误优先第 1 轮仅输出全零或全一，比例 70.8%/29.2%；第 2 轮有 16 种掩码，99% 都是“前若干候选全选、后面不选”，GT 仅 34% 有这种形状。第 3 轮在 guard 和 test 都全零，被 guard 拒绝。零输出是有效解析后的模型选择，不是 API 或解析失败。接纳曲线第 2 轮后保持不变来自版本选择保护，底层模型并非单调进步。候选顺序/数量偏差只是事后诊断，尚未隔离因果原因。

独立核验了 6 个实际适配器哈希、6 次 100 步日志、每轮 400 条实际训练输入/标签、选择决策和全部保存的测试预测。但 3,600 条更新前反馈中有 10 条无法从现有输入缓存精确恢复：重复输入曾分别生成，缓存可能覆盖了先前结果。原始权重和对应采样成员保留且可核对，不补造缺失的逐例原始输出。这限制完整训练轨迹复现，不改变已独立重算的测试成绩。新实验必须去重生成请求并保存逐例不可变反馈回执。

## 实验结束后的缓存修复

后续执行器已在生成前去重相同输入，保存与病例/候选目录绑定的不可变回执，并快照实际用于更新前反馈的输出。回归测试覆盖相同输入不同目录、无额外生成的重放以及损坏回执拒绝。已完成v0.15禁止误重跑，原执行代码由 `results/executed_source_manifest.json` 固定。修复不会补造旧10条缺失输出，也不改变本次结果。
