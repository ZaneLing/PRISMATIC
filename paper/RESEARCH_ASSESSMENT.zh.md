## 1. 论文究竟要解决什么

**让 LLM 根据当时可见的患者状态，生成更接近临床治疗需要和医生处方的完整方案；再把与参考处方的差距转化为有适用条件、能通过反例验证、能迁移到新病例的持久更新。**

需要同时回答三个问题：处方是否更准确、更全面；改进来自哪个可观测环节；随着新病例到来，改进是否持续且可迁移。安全、准确性、完整性和医生修改负担分别报告，不能用一个加权总分掩盖取舍。

### Utah：真实且有边界的动机

截至本次核查，Utah 官方列出两类相关试点：Doctronic 处理限定药物的既有处方续方，仍处于每单需执业人员授权的第一阶段；Nolla Health 的成人轻中度痤疮试点于 **2026-10-05** 开始，允许指定外用药的首次处方和续方，初期须两位医生审核。它们是限定范围、分阶段的监管试点，不能写成“AI 获得全面独立处方权”。[Utah 官方试点清单](https://commerce.utah.gov/ai/regulatory-relief-4/authorized-pilots/)

因此 intro 应从“AI 正进入真实处方工作流”引出问题：**在患者条件发生变化、历史经验持续积累时，如何证明一个处方 agent 既能更准确地作出治疗决策，又能持续改进而不破坏已有能力？** 当前住院新增订单任务不是 Utah 门诊续方任务，结果不能直接外推。

### “贴合人类”怎么定义

- **行为一致性**：药物集合、完整订单、继续/新增/调整/停药动作与记录的一致性。
- **临床需求一致性**：是否覆盖应处理的问题，是否存在可接受替代方案，是否减少医生修改量。
- **条件响应一致性**：患者条件改变时，该调整的决策会调整，不该调整的决策保持稳定。

GT 是医生采取的**可观测行动**，不是医生完整的思考过程，也不是唯一可接受的治疗方案。自动计算 GT 指标不需要等待医生评审；如果要声称临床合理、全面或更像医生决策，则需独立临床标准与已约定的两人盲评。不能以文字解释更像医生代替这些指标。

## 3. 为什么 MIMIC 只有约 20：新完成的实证分解

本次新增脚本从冻结预测重新统计 1,082 个测试 admission、三个种子，无新推理、无训练、无外部 API。结果为**事后描述**，不可据此在这个测试集上重新选方法。[代码](audit_prescription_gap.py) · [结果 JSON](prescription_gap_audit.json)

| 诊断 | 早期监督流水线实测 | 能说明什么 |
|---|---:|---|
| 每例预测药物 / GT 药物 | 5.35 / 3.51 | 多预测仍不足以提高覆盖率 |
| 每例 GT 漏项 / 相对 GT 多项 | 2.66 / 4.51 | 漏开和多开同时存在；多项不自动等于临床不合理 |
| 漏项中仍在词表内的比例 | **75.12%** | 单纯扩词表不足；主要漏项并非 OOV |
| 已在既往订单出现的目标药召回 | 39.13% | 熟悉治疗更容易匹配 |
| 未在既往订单出现的目标药召回 | **20.87%** | 新治疗需求是明确薄弱点；不等于已证明某种推理根因 |
| 药名已命中时，完整 GT 核心订单匹配 | **55.56%** | 选药之后仍有剂量/途径/单位联合不匹配 |
| 无可见血液化验的测试 admission | 584/1,082 | 部分上下文稀疏；尚未证明其因果影响 |
| 最终空输出率 | 2.74% | 当前低分已经不能主要归因于此前的 50% 空输出问题 |

已有**开发集**诊断另显示：词表覆盖 80.80% 目标药、模板库覆盖 75.36% 完整核心订单；假设完美选择，药物支持上界 F1 为 89.25%。这是利用 GT 的 oracle 上界，不是模型成绩。因此当前差距远大于词表约束本身。[开发容量审计](../upgrade_v21/results/development_capacity_audit.json)

输入实际只有年龄分箱、性别、既往可用订单和可用化验，缺少可在时点前确认的完整治疗问题、症状和临床计划。早期文本模型还把数值化验当词处理；数字表示试验在 guard 上改善 0.514 pp，但区间包含零，不能声称已解决。[数值表示试验](../upgrade_v22/RESULTS.en.md)

**改进顺序**：先补齐合法的时点前临床状态和成分/剂型映射；再衡量候选召回、选药、联合订单、最后审核各阶段的损失；最后让 RSI 学习这些可定位的流程缺陷。只增加反思文本、技能数目或输出药数没有证据保证增益。

建议形成三张结果表：①相同 MIMIC 病例、输入与药物空间的处方集合/订单主表；②公开 QA 次级表；③固定基础 agent 下 GRASP、SkeMex、Reflexion、RxRSIAgent 的进化表。每张表注明作者实现、独立实现或任务适配。论文原分数可放“文献结果”，同时列数据版本、粒度和输入，但不参与同协议排名。

## 5. 怎样把失败病例变成可验证的机制

**以下是工作流层面的机制假设，不是已经发现的神经网络内部机制，也尚未证明都是文献首创。** “模型会忽略禁忌”“记忆会负迁移”“患者条件没控制最终答案”已有相关工作，不能作为新发现直接认领。MedPIC 已讨论条件失效后仍保留风险判断；GRASP、SkeMex 已研究技能价值和退化。[MedPIC](https://arxiv.org/html/2608.03028v1)

| 待检验机制 | 现有证据 | 下一步成对干预 / 可证伪指标 |
|---|---|---|
| 产品证据正确但适用条件在检索中丢失 | 同成分顺势疗法误召回；联合药标签切断人群条件 | 同病例比较原段落、完整条件句、等长度无关补文；测条件保留、选药变化与新病例净修复率 |
| 引文真实但患者前提不成立 | 从反复输血推断透析；quote 核验仍放行 | 明确区分已知/未知/否定，核验“患者条件满足证据前提”；在条件翻转对和不变对同时评估 |
| 药物知识与治疗阶段不匹配 | 白喉活动期治疗与暴露前疫苗混淆 | 仅改变时间/治疗阶段、保持药物和检索预算；验证指南检索是否优于单加说明书 |
| 多开不能修复漏开，审核也可能误删必需治疗 | MIMIC 同时低 P/R；公共修复出现净退化 | 固定候选列表，对选药与审查分别消融；记录 TP 被删、FP 被留、未入候选的 GT |
| 记忆效用依赖执行模型与上下文 | Gemini 固定工具 54.45%，迁移技能 51.62% | 固定技能文本和证据，换执行模型；等长度占位记忆、工具专用记忆、原始错误记忆对照 |
| 正确药名不保证可执行订单 | 已命中药名的核心订单仅 55.56% 匹配 | 生成式剂量与结构化订单核验器对照；字段准确率、联合正确率、未知/拒绝率一起报告 |

用一个修复成功案例只能提出假设。每条机制需要：预先定义错误标签 → 在训练病例中形成规律 → 正例与成功反例 → 单模块干预 → 重新执行并观察中间状态 → 同类独立病例验证 → 药物/患者/疾病或执行模型迁移。

最近产品/句子/路由修复均未通过 proposal 的逐任务无退化门槛；400 个训练病例上由 269 到 273，不代表独立收益。112 次更新尝试最终没有持久更新。**这些结果说明当前 RSI 尚未成功，不能用增长的日志数量充当能力增长。**

## 6. 如何验证“套在不同 LLM 上都有效”

把目标改为可检验的范围：至少三个预先选定模型家族，覆盖强弱能力；同病例、同来源、同工具、相同预算分别比较 direct、固定工具 agent、最强匹配外部 agent、RxRSIAgent。预算确定后再运行，不根据测试成绩替换基础模型。

保留两个互不混淆的实验：

1. **冻结迁移**：模型 A 学到的状态原样给 B/C，不再学习；这才能支持框架/技能可迁移。
2. **各自学习**：每个模型使用同等训练经验独立进化，检验适应性；不能写成零额外训练迁移。

记录每轮 seen cases、原始候选与接纳状态、技能/检索/工具规则的差异、触发量、修复/退化、费用。建议 0/100/200/400/800/1,600 个独立病例与三个病例顺序种子；这是下一次研究的设计，不是已跑的轮数。固定组件、等长记忆、打乱反馈、普通监督校准和等反馈最佳搜索必须同时存在。全轮次冻结后在独立队列统一测试，不能根据测试选择最优轮次；重复开发集的接纳曲线必然偏乐观。

临床指标沿用[评审协议](CLINICAL_EVALUATION.zh.md)：治疗目标覆盖、重大错误病例率、完整临床正确订单率，并列漏项、多项、DDI/肾功能处理、适用证据、监测和医生修改负担。补充 continue/start/change/stop 动作一致性与病情变化响应。缺失字段只报未知和评估覆盖，不能默认正确。

## 7. 数据集是单病种还是多病种

| 数据 | 疾病覆盖与病例结构 | 测什么 |
|---|---|---|
| RxSafeBench | 跨十类专科的模拟问诊，可含合并症和并用药；不保证每例有多病共存 | 一次三选一的安全选药，不是整张多病种处方 |
| RxQA OpenFDA | 广泛药物信息问答，不按一个疾病队列定义；部分题涉及患者条件 | 四选一药物推理，公开 300 题；未公开的 BNF 300 题没有测 |
| MedPIC | 年龄、妊娠、肾功能等条件下的用药规则与反事实；不是单一疾病队列 | 条件变化后的规则适用性；多选题不等于多病种处方 |
| MIMIC-IV | 异质真实住院/ICU 人群，可有合并症与多药；不能声称每例均为多病共存 | 一个方案预测未来新增/变更订单；另一个方案预测完整就诊药物集合 |

此外，历史实验还做过 **eICU**：跨医院、异质 ICU 人群，8,005 个测试 stay 来自 16 个留出医院，预测原生 HICL 订单。它是在 eICU 内训练后的跨医院测试，不是 MIMIC 模型零样本迁移，也不是当前 LLM agent 的成绩。[已完成历史结果](../upgrade_v25/RESULTS.en.md)

[RxSafeBench 定义](https://arxiv.org/html/2511.04328v1) · [RxQA 发布范围](https://github.com/Google-Health/rxqa) · [MedPIC](https://arxiv.org/html/2608.03028v1) · [MIMIC 处方表](https://mimic.mit.edu/docs/iv/modules/hosp/prescriptions.html)

未来应分别报告常见/少见病、单病/经临床分类确认的多病共存、药物负担和新旧治疗；诊断代码数量不能直接当疾病数。若使用后验完整诊断分层，须标为描述分析且不进入决策时点输入。
