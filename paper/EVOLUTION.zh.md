## 1. 更新机制：明确借鉴并引用代码

复用GRASP作者核心，固定提交`9d7d125a3e9b46ed591692475eb07aff4ae67d34`；审计确认核心未修改。我们提供处方任务、证据接口和评测，不把作者优化器当成原创。

1. 固定LLM、说明书工具、资料快照和输出协议；初始化空技能库。
2. 每轮处理157／157／157／154个新训练病例，保存预测、标签差异与失败类型。
3. 提出4个候选技能修改；源码支持ADD、MODIFY、REMOVE。本次实际接受ADD一次、MODIFY两次。
4. 在40个训练探针上比较候选与重新运行的当前状态：目标为20个失败和20个成功病例。第1轮探针来自本轮训练病例；后续来自先前训练批次。独立重建的探针与当前提议批次重合数为40／0／0／0。第1轮不属于独立验证。
5. 计算`S=(修复数−当前状态重跑修复数)−(退步数−当前状态重跑退步数)−新增无效动作退步数`。只有S>0且候选退步数不超过当前状态重跑退步数，才可能保留最高分候选；额外修订仍按同一规则比较。
6. **开发集只测了初始和整个epoch结束两个状态**：190/387→206/387；没有每轮开发集曲线。选中最终状态后冻结，才重放中间检查点用于测试／迁移分析。测试分数不参与选版本。

| 轮次 | 累计病例 | 技能数／正文词数 | 实际修改 | RxSafe正确数/988 | RxQA正确数/300 |

| 0 | 0 | 0 / 0 | 无持久技能 | 499 | 188 |

第1轮复用未变化状态的预测，不是一次新的独立测试。正文词数按去掉元数据后的空白分词计算；**词多、文件多不代表能力强**。文本修订描述的是模型写了什么，不代表其临床规则已被验证。

## 4. 每个模块的“增长”分别是什么？

| 模块 | 实际更新情况 | 可支持的结论 |
|---|---|---|
| 语言技能记忆 | 0→1个保留技能，新增1次、修改2次；711→645→774词 | 改变了行为；测试净增很小，迁移退步 |
| 说明书检索 | 技能实验期间固定；之后由研究开发修复 | 同300题片段覆盖1→214，剂量0→193；没有新答案准确率，不能叫自主工具进化 |
| 订单工具 | 独立eICU组件学习 | 同药物集合下订单F1 0.02334→0.02838，完整率53.67%→51.13%；不能拼接成QA agent收益 |
| 临床检查 | 人工定义18类接口，12项结构测试通过 | 工程覆盖，不是临床正确率或病例驱动增长 |
| 模型参数／输出协议 | 当前保留的学习实验中固定 | 更新次数为0，不报告虚构增长 |

## 5. 下一轮需要证明的内容

至少三种子、独立测试病例、相同预算，比较固定记忆、普通反馈、打乱反馈和去掉回归门控。对每个学习对象记录新增／修改／删除、来源和前后行为；在固定其他模块的条件下做替换实验。完整订单还要逐轮报告[医生视角终点](CLINICAL_EVALUATION.zh.md)，证明覆盖改善没有以严重错误增加为代价。未知／不足数据不能计成通过。

目前公开基准已被历史研究观察，曲线属于探索性证据。上述审计没有恢复长期队列、没有新API费用，也没有生成新的临床效果分数。
