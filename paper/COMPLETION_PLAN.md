## 1. 最终要交付什么

最终交付是一篇有可复跑证据的英文论文，回答两个问题：**完整处方 harness 是否提高处方质量；随着经审定病例积累，系统是否更会判断辅助药与液体医嘱的适应证。**

交付包含：英文 AAMAS LaTeX 正文及编译验证、同数据跨方法主表、病例增长曲线、机制消融、双人临床盲评、公开次级集结果、真实 FHIR 工具评测，以及代码、配置、汇总结果、运行清单和版本记录。每个完成项单独记结果并同步 GitHub；没有跑完的格子标待测。

本轮先交付完整计划，并执行 P00 模板/正文核对和 P01 标签缺失审计。之后按依赖顺序推进；临床评分与外部资源缺口单独登记，其他可运行工作继续。

## 4. 数据与评估协议先冻结

### P01：识别标签缺失和观察时点

1. 对全部队列及现有 train/val/test 分别统计：六小时完全无原始处方、有处方但没有 ATC 标签、至少一条已映射处方。保留原始数量和映射来源。不能把前两者合并成“无需药物”。
2. 报告每个给药途径、药物类别及辅助药类别的映射覆盖；罕见类别的小计合并。找出盐水、载体液和冲管液是否被系统性漏映射。
3. 当前 GSN/药名回退映射用到了整个训练患者池，而模型只抽 40,000 次入院。先披露这一额外标签资源；正式病例增长实验必须使用固定外部词典，或在每个增长检查点仅用当时可见训练病例重建映射。
4. 为每个输入字段记录 observation_time、availability_time、source。检验若有 storetime，要求在决策时已可用；无可靠时间戳的字段不可直接声明为入院时可见。区分医嘱 starttime 与医生实际下单时间。
5. 当前测试集已经多次看过结果，应称开发测试集。正式确认集从从未参与调参、检索、映射训练或错误反馈的患者池锁定，记录成员哈希；若发现全体测试患者已参与选择，则不再声称该池是从未查看的最终测试。

**产物：**`upgrade_v4/results/label_observability_audit.json`、数据字典、时间审计、受限病例清单、标签缺失敏感性分析。

**验收：**患者重叠为零；所有最终输入时间违规为零；无标签人群组成可解释；映射歧义及未知项显式保留。映射覆盖没有预设“达到某个百分比就安全”的替代判据，须完成分层误差审查后冻结目标空间。

### P02：统一药物与完整医嘱表示

- 历史集合主表采用 ATC-L4；完整处方另保留 RxNorm/本地规范化成分、剂型、浓度、途径、剂量、频次、疗程。
- 映射来源依次为固定版本的公开/授权词典、可追溯的精确匹配、训练内回退。模糊匹配必须经人工审查或保留不确定，禁止静默补码。
- 每条辅助药有 indication、evidence_ids、uncertainty。盐水额外有 purpose（复苏/维持/补充/载体/冲管/未知）、volume、rate、reassessment；缺必要信息允许弃权。
- ATC-L4 的同类药不可自动视为可互换；同成分去重与药物相互作用在成分/具体医嘱层检查，再单独投影到类别层报告。
- DDI、肾调整、禁忌知识固定版本、授权范围和适用条件，报告覆盖率；未知知识覆盖不得计为“安全”。

**产物：**订单 JSON schema、映射版本、训练词表、DDI/分子覆盖清单、同一评分器。固定 Top-5 保留为历史兼容指标；正式指标允许可变药数及弃权，阈值只在验证集选择。

## 5. 对比谁：方法矩阵

| 方法 | 必须保留的机制 | 实现与定位 | 进入什么表 |
| --- | --- | --- | --- |
| 流行度、LR/SGD | 训练频率或直接多标签预测 | 本地基础对照 | 同题主表基础行 |
| Case retrieval | 只检索训练病例，固定 K 与上下文预算 | 原始病例检索，记录检索患者与时间 | 主表 |
| Direct local LLM | 单一固定本地底座、规范订单输出 | 与所有 LLM 臂共享底座及可用输入 | 主表 |
| 普通二次回答 | 同底座，同调用上限，无特殊记忆或检查 | 计算量对照 | 主表或消融表 |
| 原版 PRISMATIC | 原 ZIP/代码的 DSWA、DFPC、代理分工 | 独立核查原实现，缺项逐项说明 | 主表历史版本及机制消融 |
| GAMENet | 就诊编码器、药物图记忆与历史读取 | 官方代码优先；入院时点输入改造须标 adaptation | 通过协议后进入主表 |
| SafeDrug | 分子表示、DDI 约束 | 官方 archived 分支是原论文复现起点；ATC-L4 改造重新训练、重新建立分子映射 | 通过协议后进入主表 |
| SafeRx-Agent | 按论文规范实现其患者上下文、知识和验证流程 | 当前未确认可执行官方实现；优先继续核查，否则独立复现并列规范差异 | 通过同数据验证后进入主表 |
| PRISMATIC full | 结构化状态、辅助医嘱候选、经验检索、独立检查、有界修订、弃权、轨迹 | 本项目完整实现 | 主表核心行 |
| HealthFlow / EMR 经验策略 | 经验提取、组织、检索/更新机制 | 各自任务不同；实现同底座的经验策略适配，不能冒称原论文完整复现 | 病例增长/机制表，不抄原分数 |
| DREAM 框架中的其他近期方法 | 依具体方法而定 | 核查模型、数据和许可证后最多补 1–2 个强对照；DREAM 是评测框架而非单一方法 | 补充稳健性表 |

**处理输入不兼容：**先确定每个方法是否能用同一入院快照。不能直接给 GAMENet/SafeDrug 看出院诊断，也不能将主诉词随意冒充原诊断码。可建立对所有方法共享、训练集构建的入院状态编码器，并将其影响作为敏感性实验。若改变了原方法关键假设，就在另一个“标准回顾性就诊任务”面板验证忠实实现；该面板需所有参与方法使用同样回顾性输入，不能与入院决策主表混排行。缺失 DDI 图或分子编码时不得用全零图代替后仍称完整 SafeDrug/GAMENet。

官方资料已在 2026-10-14 核查：[GAMENet](https://github.com/sjy1203/GAMENet)、[SafeDrug](https://github.com/ycq091044/SafeDrug)、[SafeRx-Agent](https://arxiv.org/abs/2605.29146)、[DREAM](https://github.com/novzyg/DREAM)、[HealthFlow](https://github.com/yhzhu99/HealthFlow)、[EMR](https://arxiv.org/abs/2609.15161)。HealthFlow 是 EHR 分析流程，EMR 是临床推理经验机制；二者在此作为待验证的经验策略参考。

## 6. 实验如何逐项做

### E01：真正跨方法的处方主表

**输入：**P01/P02 冻结后的同一 MIMIC 入院快照。训练/验证/测试患者清单相同。先用现有 40k/4k/4k 做工程和开发验证，再在冻结的完整训练池及最终确认集上跑正式结果。

**步骤：**先 LR/SGD、检索和 direct local LLM；随后 GAMENet、SafeDrug 的可核查实现；再原 PRISMATIC、SafeRx-Agent 和 full harness。每个方法先做少量病例 schema、时间和评分一致性检查，再扩大样本。能执行完但输入不一致的结果不进主表。

**预算：**LLM 主比较先固定一种可在授权本地环境运行的底座，统一输入、输出 token 上限、最大工具步数和同预算重复回答对照；同时报告实际 token、调用、时间与峰值内存。传统网络用相同数据、预先固定的调参试验数和早停标准，报告训练资源，不能声称与 LLM GPU 时间严格等价。模型选择先做 50 例本地吞吐/格式测试，记录实际模型 ID、权重 revision、量化和硬件后固定。

**指标：**历史集合 Jaccard、micro/macro F1、PR-AUC、P/R@5、药数；另报 mapped/unknown 覆盖。临床行使用 E04 的严重错误和指征评分。DDI 报告可评对数、覆盖和严重性，不能用推荐空集合换取低 DDI 而不报漏开。训练随机种子至少 3 个，预算允许时 5 个；LLM 非确定性用固定子集重复，不能将温度 0 当绝对确定。

**交付：**表 2A 历史集合方法比较，表 2B 完整处方临床比较；每个格子链接 run_id 与汇总 JSON。传统 ATC 集合方法的剂量/速度为 N/A，不能凭空补齐。

### E02：病例积累与“进化”主实验

**要区分：**经验库进化（底座权重冻结）、策略/规则版本升级、模型参数训练。第一阶段主做前者，不能写成 model weights 越来越懂医生；若声称参数学习，另做 SFT/偏好学习实验并报告训练。

**病例数：**0、250、1k、4k、16k、40k；数据充分再增加完整训练池。所有检查点使用固定测试患者，反馈只来自训练流。每例先预测、再获得训练反馈、再更新记忆，测试反馈永不回写。MIMIC 去标识时间存在患者间偏移，未经验证不把跨患者时间排序称为真实历年部署。

**对照：**冻结模型；固定规模静态 RAG；持续加入原始病例的 RAG；仅成功案例；成功+失败案例；经双人/规则审定的经验记忆；经验更新但去掉回滚门控。增加随机经验与同样 token 长度的无关经验作为机制负对照，仅在研究评测中运行。

**控制：**每次检索 K、上下文长度和推理调用固定；病例流至少 3 个固定顺序；相同患者的多次入院不能流向不同集合。历史行为数据增长和临床审定数据增长分别画图，不能把 40,000 条未审定记录称为 40,000 个专家理由。

**指标：**辅助药指征精确率、重大漏开、无指征药、盐水用途/量/速度、肾调整、严重错误、弃权；历史 AP/F1 另图。报告各检查点区间、末点差值、学习曲线面积、回归病例和记忆成本；不强求曲线单调。

**交付：**固定病例增长图、经验版本日志、升版/拒绝/回滚记录。升级门槛由验证集与临床评审先固定，不得看最终测试后调整。

### E03：机制消融和计算量公平性

围绕同一 full harness 去掉：辅助治疗模块、病例检索、指征证据、独立药理检查、修订边界、经验质量门控、失败案例记忆。原版 DSWA/DFPC 各自消融，避免把旧机制改名当新贡献。对照普通二次回答、相同工具/调用预算的单代理；额外检索和验证工具消耗计入总预算。

先在固定开发子集做全消融筛查；正式确认集仅运行预先保留的关键消融。至少报告辅助药精确率与漏开率的双向变化、严重错误及每例成本，避免仅优化一个方向。

### E04：两名临床/药师双盲评审

已有两位评审者。先用训练/开发病例做 20–30 例标准校准，修订评分规则后冻结；正式评审中的两份评分独立保留，争议用记录共识或第三方仲裁。评审者看不到方法名、其他人评分和历史处方；实验执行者掌握方法编码，因此准确称“评审者对方法身份与彼此评分双重盲法”，不宣称执行者也盲。

200 例八层抽样作为探索性临床起点，按原始各层人群数加权；重复入院按患者聚类。正式确认需要新的锁定患者或如实说明已探索的数据，样本量由试评所得差异、事件率与配对相关性估计，不能事先保证 200 例足够。

病例卡只含决策时可用的病史、过敏、生命体征、药物核对、体重、肾功能、电解质和液体相关信息；缺失标未知。每个候选订单按指征、漏开、无必要药、DDI、肾调整、盐水用途/量/速度评分；未知和不可评分别记录。ATC-only 方法不能评剂量。临床主终点为每例至少一项严重/危及生命错误；评分一致性、分母、分歧和仲裁均报告。

**交付：**本地病例卡、A/B 盲标包、双评分表、仲裁表、加权汇总与患者配对区间。评审者提交前不生成临床结果数字。

### E05：公开次级集全量补齐

- [RxSafeBench](https://github.com/CAS-SIAT-XinHai/RxSafeBench)：固定源文件及去重协议的 2,000 题；保留 direct、普通复核、轻量 harness 的已有全量结果。下一步扩展另两个固定 OpenRouter 模型并增加真实知识检查臂，公开模型元数据与提示版本。
- [RxQA](https://github.com/Google-Health/rxqa)：全部公开 OpenFDA 300 题；补上相同底座的 direct/repeat/知识复核；不可称包含未公开的 BNF 部分。
- 顺序/泄露敏感性：重新排列选项、保留正确答案映射、按同题配对；RxSafeBench 中答案药名直接出现的题单独报告；开发曾用题目如实标记。引用证据出现不能算医学正确，必须检查知识来源与适用条件。
- 记录准确率、有效率、改对/改错、API 失败、成本、延迟和配对区间。失败计入主要分母，重试策略预先固定。公开题可经 OpenRouter；受限 MIMIC 留在授权环境。

费用先以小批次实测估算全量调用，记录 `max_requests`、token 和花费上限并可恢复运行。模型目录在运行时核查，不能拿过时价格或名字承诺预算。

### E06：MedAgentBench 真实工具与状态

按[官方实现](https://github.com/stanfordmlgroup/MedAgentBench)部署 Docker FHIR、任务控制器及官方参考评分文件，固定镜像 digest 与代码提交。先 10 个任务验证 GET/查询、下单、提交后读取和环境 reset，再在官方 300 任务上执行 direct tool agent、同预算普通规划器和 harness。

每任务隔离或重置初始状态，记录工具调用、错误、重试、最终资源内容。指标包括官方成功率、schema 合法率、重复下单率、错误患者写入、状态验证、延迟/费用。重试写请求必须有幂等策略；不能以“模型回答完成”判定状态成功。未取得参考评分器或运行环境时保留环境失败记录，不用文字模拟代替。

### E07：鲁棒性与泛化
