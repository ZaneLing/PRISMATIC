# 研究更新：从“记忆增长”到有证据的处方能力提升

## 新调研带来的改动

| 原始研究 | 研究对象 | 我们采用的设计原则 |
|---|---|---|
| [GuideSkill，2026年7月](https://arxiv.org/html/2607.26160) | 将指南诊断条件编译成可执行规则，再用标注病例扩展 | 条件必须可检查；指南工具的人工工程与病例学习分开归因。它评估诊断，不能直接拿诊断分数填处方主表。 |

## 已落实的 agent 结构

`决策时可用病情 → 固定 LLM 与训练集检索 → 草稿订单 → 条件技能解释器 → 带来源的适用性预筛 → 研究输出`

学习支路是：

`训练病例与 GT 的逐项差异 → 汇总共性错误 → 具体诊断条件 + 目标药物 + 增补/删除/联合字段替换 → 从伤害病例生成例外 → proposal/guard 验证 → 冻结逐轮技能 → 新患者与跨模型检验`

本次学习器是有标注反馈的确定性程序归纳器。增长的是外部规则记忆；没有更新 LLM 权重，也没有让 LLM 自主发明药理知识或工具代码。它是 RSI 命题的一部分，不能直接写成完整 RSI 已成立。

### 临床工具

新增三个固定说明书核验模块：[二甲双胍](https://dailymed.nlm.nih.gov/dailymed/drugInfo.cfm?setid=4e4c4ba9-65c6-4273-8f6b-2423ab521dad)、[依诺肝素](https://dailymed.nlm.nih.gov/dailymed/lookup.cfm?setid=d8afb29f-cbed-43bc-809f-09b30fca28f5)、[依普利酮](https://dailymed.nlm.nih.gov/dailymed/fda/fdaDrugXsl.cfm?setid=bcd7595f-700f-48ba-bf83-05a995ce0731&type=display)。只做部分条件预筛；返回来源与命中理由。缺失/过期/单位不匹配的测量返回未知；不把 eGFR 当作 CrCl，不把没有既往订单当作首次用药，不自动推断活跃疾病或给出调整剂量。边界测试通过不等于临床有效性得到验证。

## 从开发失败继续修正

192 个反馈病例中，仅2种完整联合订单在至少3位患者中重复出现。最初合格提案全部为删除，说明补漏与字段修复受到模板稀疏性限制。因此，在读取新测试结果之前，新增一项修正：调用此前40000个训练住院中的重复联合模板，按独立患者计支持度，只允许反馈中已经出现的模板进入提案；原有支持门槛和验证规则不降低。原反馈模板方案保留为消融，对应记忆回放获得相同模板资源。该修正在测试推理开始后、指标揭示前冻结，属于开发驱动的探索性修正。

## 本轮证据标准

- 三种病例顺序、两种本地模型，每轮都保存状态；不按测试分数挑最好的一轮。
- 漏开、多开、完整联合订单差异同时报告配对置信区间；另报共同药物上的字段错误，避免用删药冒充剂量修复。
- “多系统疾病”只是记录诊断类别的操作性分组，不等于经过验证的慢性多病共存。
- 规则有诊断字符串并不保证具有临床意义；有统计支持也不构成停药适应证。规则与处方均需独立适当性审查。
- 必须超过单纯反馈回放，才有证据说明总结技能带来了额外收益。

后续应解决的关键是治疗意图和具体疾病证据能否支持**有效增补与字段修复**。当前六小时订单预测的 GT 本身，无法完整证明临床上应如何给患者开药，更不能据此宣称发现了临床因果机制。

### 执行层根因追踪

14个新增字段修复候选共896次proposal病例检查：787次条件不匹配、97次草稿缺少目标药物、12次实际修改联合字段。12次修改均未改变任何主指标错误数，即执行发生了，但没有修正参考错误。这个结果只说明当前程序语言的局限，不能推广成临床字段修复不可能。
