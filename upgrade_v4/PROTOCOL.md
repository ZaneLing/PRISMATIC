# PRISMATIC v4：已冻结的开发实验协议

版本：`v4-development-20261014-r1`。这是已执行开发实验的协议，**不是前瞻性注册或最终确认性试验**。机器配置见 [protocol.json](protocol.json)，订单定义见 [order_schema.json](order_schema.json)。

## 1. 时间与输入

决策点为急诊停留期间的住院入院时间。主分析输入为主诉、acuity 与入院前 charttime 的既往用药文本，命名为 **admission proxy**：triage 没有逐行时间戳，medrecon 没有 storetime，因此不能宣称完全验证了入院时可用性。信息缺失不推断为正常。

实际执行三种输入视图：完整 admission proxy、仅 home_meds、无患者文本。后两者用于量化信息依赖；它们不能证明主输入无泄露。对新增检验另冻结规则：同一 hadm_id，入院前 24 小时，charttime 与 storetime 均非空且不晚于决策点，数值可解析，每项取最后一条。无 hadm_id 的检验不跨就诊猜配。筛出的检验保存在本地，但未临时加入已冻结的本轮方法输入。

## 2. 队列、映射和未知标签

沿用全部 201,750 次合格入院和患者哈希切分；40,000/4,000/4,000 的确定性样本与旧版相同。该测试集已经被查看，只能用于开发。确认集仍待另行锁定，不能将本轮结果称作最终泛化结果。

先将原始 NDC 与公开词典 NDC 统一为无歧义 11 位；有歧义不映射。GSN/药名回退只从**本轮 40,000 条训练入院记录**构建，支持度至少 10、纯度至少 98%。不使用整个训练池或测试标签。病例增长实验在每个检查点重新构建或固定外部词典；本轮 40k 词典不能直接复用于小样本增长。

保留 raw_orders、mapped_orders 和映射来源；未映射订单保留原始药名、剂型、浓度和途径，规范成分 ID 为未知。ATC-L4 是类别，不能充当 RxNorm 成分或剂型 ID。无原始订单、有订单却全未映射、至少一项已映射分别统计。

主要工程指标为全病例**可观察标签重合**：保留空标签病例，但明确其不是“无药物指征”临床负例；另报至少一项标签病例的条件敏感性分析。后者按未来标签条件选择了评分子集，不能包装成无偏人群性能。任何未观察匹配都不能直接称临床误开。盐水名称代理单列，不伪造 ATC 编码，不从药名推导复苏/维持/载体/冲管用途。

## 3. 完整订单协议

每条订单包含：药名、规范成分 ID、剂型、浓度、ATC-L4、剂量数值与单位、途径、频次、疗程、指征、患者证据 ID、不确定性；液体另有用途、体积、速度与复评。

- 已知值必须有来源；未知统一为 JSON `null` 和 uncertainty，不能补默认剂量/速度。
- 原始剂量是范围或文本时保留原文，不强行当成单值。模型输出的数值只是待评草案。
- 盐水的用途只能取 resuscitation、maintenance、replacement、carrier、flush、unknown 或 null；不能仅因名称含 saline 就填用途。
- E1/E2/E3 引用本患者信息；训练检索 R1 等不能充当本患者证据。引用存在只通过结构检查，临床支持关系另交评审。
- 检查缺字段、非法数值、同成分重复、无效引用和液体信息缺失；每次最多一次修订，保留原稿与最终稿。
- 状态仅为 `abstained`、`needs_information` 或 `needs_clinical_review`。空处方不代表安全。缺乏成分级临床 DDI/肾调整规则时始终标未知，不输出“可执行/安全”。

结构完整与临床正确分别评估：报告原始输出满足完整 schema 的比例；规范化只补 null，补完后的比例另报。剂量/盐水/肾调整正确性等两位评审者提交评分后报告。

解析修正 r2：格式或级别不符合 ATC-L4 的字符串保留在 uncertainty 原始值说明中，对应规范字段置 null；不截断猜码。原始 r1 失败结果继续保存，规范化成功率不替代模型原始正确率。

## 4. 方法与预算

全体开发测试集：流行度、30 邻居病例检索、TF-IDF/SGD（种子 17/42/73）；同 80 个训练高频 ATC-L4、每例 5 类，召回分母包含全部已映射目标。方法训练资源不同，只保证病例和任务一致。

GAMENet 采用**独立入院文本、单次就诊适配**：使用作者代码的图网络和读出模块，两个 token 通道替代诊断/操作编码，单次就诊没有历史动态记忆读取。固定三种子、5 epoch、验证集选最佳 epoch；批处理前向与作者单例前向数值核对。真实 TWOSIDES 来源建立研究图，缺资源覆盖显式报告；不是原论文忠实复现，原始训练策略也不同，详见 [graph_protocol.json](graph_protocol.json)。

50 例嵌套测试子集：同一本地 Qwen3-4B 固定权重和温度，直接回答、普通二次回答、训练病例 RAG、bounded harness。直接/普通复核共享首答，RAG/harness 共享检索首答；每次 192 输出 token 上限，普通复核和 harness 各 2 次调用。检索增加了输入 token，因此是调用上限一致，**不是严格总 token/成本相等**。分别报告实际 token 和时间。非法输出按空集计入全部分母。

完整订单生成另外固定前 10 例、最多两条订单、每次 640 token，比较单次草案和带检索的一次修订。此项不宣称等调用因果比较；只看结构、未知处理与待评订单。

## 5. 解释边界与复跑

TWOSIDES 类别图是研究相互作用关系，不是可执行临床规则；缺关系不代表无相互作用。SafeDrug 所带分子映射为 ATC-L3，不能将其无修改冒充 ATC-L4；SafeRx-Agent 的当前诊断/操作、专家路由和知识资源与本入院快照不同。未达到可比性条件的行继续留空。

研究代码及汇总可公开；逐例记录、模型权重、盲评卡留在受限目录。复跑命令与实际结果见 [结果报告](RESULTS.zh.md)。所有新方法变更须新 run_id，不覆盖已有负结果。
