# v0.23：错误反馈的同预算机制对照

## 要回答什么

按自身错误学习，是否真的比普通学习、或同分布随机权重更好？本轮承接已完成的数值状态试验；表示工程本身不算自主RSI。

## 已执行的协议

- 数据：v0.21时间可用性队列，40,000训练 / 2,000候选验证 / 2,000退化检查 / 1,082测试住院。测试集此前已观察，本轮结果属于探索性复用。
- 三个种子42、137、2026；累计8k、16k、24k、32k、40k五轮。种子同时改变病例顺序和优化随机性；轮次不代表真实时间部署。
- 三组：普通权重；当前接纳模型的错误权重；同一批错误权重随机打乱。
- 固定：初始8k拟合的词/数值特征、128原始药名、更新代码、七个阈值和接纳规则。不调用LLM或API。
- 相同预算：128分类器各精确训练60轮，同种子各组病例及顺序相同。初始模型共享；订单工具只看当轮已经见过的病例。
- 实际进化对象：策略参数、持久病例权重、订单工具参数和接纳状态。全部选择冻结后才统一生成测试预测。
- 核验：从旧接纳模型重新推理反馈，独立重算权重；核对分布、训练轮数、工具成员；独立重算预测，保留配对患者区间、拒绝版本和退化。

三个训练进程已真实启动。全部种子冻结后，完成队列依次评价、独立复核和生成报告；部分检查集结果不填作完整测试主表。协议已在训练前随提交`9550d261`推送。

## 复现与文件

依次准备数据，运行三个种子的`train.py`，全部结束后运行`evaluate.py`、`audit.py`、`report.py`。评价器会拒绝未冻结的选择。`protocol.json`保留完整协议，`results/journal_seed_*`记录已经发生的状态变化。病例、权重和逐例预测留在本地受限目录，仓库只同步代码、哈希和汇总。

完成报告将写入`RESULTS.zh.md`和`RESULTS.en.md`。
