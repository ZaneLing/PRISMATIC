# v0.31：随机候选位置下的参数进化

## 1. 动机与已实现对照

v0.26发现训练后的适配器几乎总是选择展示在前面的连续一段。本次本地实验保留原检索排名、候选药物身份和完整订单字段，只在监督训练时随机化展示位置。四种方法区分表示修复与错误反馈的作用：原排序普通训练、随机位置普通训练、随机位置自身错误优先、随机位置打乱错误权重。

三个种子各按已登记顺序接收三批600例患者互不交叉的反馈病例。每轮从累积病例中不放回抽取400次住院，进行100步、批量4的QLoRA更新，使用相同Qwen3-4B骨干的最后八层。模型先预测新病例，再根据这些输出计算抽样优先级；早期病例保留当时的更新前错误，不冒充每轮重新评估全部旧病例。候选工具和记录订单模板不进化。

用100例proposal在原排序及打乱排序两个视图上选择检查点，基础模型也是候选；训练始终从最新原始适配器继续。每个种子的四种方法均完成三轮并冻结后，才对200例报告用guard运行全部原始检查点，比较原排序、随机排序、倒序。原500例测试病例不再纳入。本版属于既往入院代理任务上的探索性开发实验，仍有录入时间证据不完整的局限，不生成新剂量。

## 2. 真实执行与数据完整性

- Completed optimizer runs / 已完成训练回执：**1/36**
- Updates with completed proposal evaluation / 已完成proposal评价的更新：**1/36**
- Unique local model responses saved / 已保存本地唯一模型响应：**1288**
- Audited complete seeds / 已完整核验种子：**0/3**

数据核验覆盖33,300个展示版本：患者角色无交叉、候选集合和真值保持一致、目标未截断。最长完整序列1005个token，低于1,536上限；每个目标69个token。十一项合成执行检查覆盖标签重排、提示不含真值、打乱权重分布和损失掩码；这些是完整性检查，不是性能提升。

在生成／拟合前，合成探针证实已安装训练器每个序列会额外监督一个末尾填充目标。四臂统一采用排除该位置的完整回答损失，通过包装器传入，不修改已安装库。该发现不证明它导致了历史训练崩溃；本版原排序普通训练对照也采用相同修正。
